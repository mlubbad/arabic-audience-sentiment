# WO-10 (Codex): stopping impersonation always exits; OAuth error codes are never empty

Mirror of GitHub issue #62. **The issue is the source of truth**; this copy exists for agents
whose token can't read issues. If they differ, ask.

- **Branch:** `codex/wo-10-impersonation-exit`
- **PR title:** `WO-10: impersonation always exits; non-empty OAuth error codes` (body starts
  `Closes #62` and fills the PR template)
- **Frontend only.** No migration, no edge-function change, no deploy.
- Line numbers are from `main` at `6a1e0ea`.

## Why
**1. A platform admin can get stuck impersonating a user.**
- `apps/web/src/impersonation.tsx:145-184`, `stopImpersonation` returns early when
  `admin_stop_impersonation` errors or throws. That leaves `sessionStorage[STORAGE_KEY]` and
  `impersonatedUser` intact.
- The RPC only writes an `impersonation_ended` audit row. Impersonation itself is client state.
- So a failed audit write traps the admin in the target user's view. Leaving impersonation
  reduces privilege, so exit must never depend on the audit write.

**2. An empty error code becomes "unknown" on screen.**
- `connect.ts:73` and `connectResult.ts:47` use `body.code ?? fallback`, which lets `""`
  through.
- The edge functions can emit `{"code": ""}` when PostgREST's code is empty.

## Tasks
1. **`stopImpersonation` always exits locally:**
   - Call the audit RPC first.
   - Then, whatever its outcome, clear the storage key, set the user to null, invalidate
     queries, navigate to `/admin/users` (`?demo=1` in demo), and set `loading` false.
   - If the audit write failed or threw, or there is no Supabase client outside demo mode,
     show a distinct toast after exiting: the session ended, but the end event wasn't
     recorded. Use a new string key in `strings/ar.ts` and `strings/en.ts`, appended only.
2. **Non-empty error codes:** in `connect.ts` and `connectResult.ts`, accept `body.code` only
   if it is a non-empty, non-whitespace string. Otherwise use the existing fallback.
