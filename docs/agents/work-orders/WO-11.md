## Why
WO-9 (#61) made the ops snapshot read `private.video_comment_stats` instead of scanning about
195k comments. Five statement-level triggers keep that table exact
(`supabase/migrations/20261003120000_ops_snapshot_video_stats.sql`). The triggers cover every
write path that exists today, but some changes can still bypass them:

- **An `UPDATE` that moves a comment.** There is no `UPDATE` trigger on `public.comments`. No
  current path changes `video_id` or `workspace_id`: the three upserts only set text, likes,
  provenance and `last_seen_at`, and `purge_comment_text` only clears text. But a future one
  would silently desync both the old and the new video.
- **`TRUNCATE`**, or manual SQL run with triggers disabled (`session_replication_role =
  replica`). Neither fires the row-change triggers.
- **A bug in a future trigger change.**

The snapshot shows these counts as truth, so drift would be invisible. This WO adds two things:
- a guard that makes the first case impossible;
- a nightly reconcile that finds any remaining drift, corrects it, and reports how much it
  found.

## Tasks
1. **`private.reconcile_video_comment_stats(w uuid) returns jsonb`**, `security definer`,
   `set search_path = ''`.
   - Compute exact `total` and `analysed` for every video in `w`. Use the same definitions as
     the WO-9 seed: `analysed` is the number of distinct comments with at least one
     `status = 'succeeded'` prediction.
   - Compare with the stats table, treating a missing row as `(0, 0)`.
   - Collect only the `(workspace_id, video_id)` pairs that differ, and pass them to the
     existing `private.refresh_video_comment_stats(pairs)`. Do not write the table any other
     way: that helper already holds the lock-then-recompute discipline that prevents lost
     updates against concurrent triggers.
   - Return `{"workspace_id", "videos_checked", "rows_corrected"}`.
   - Revoke from `public`, `anon` and `authenticated`. Grant execute to `service_role`.
2. **`private.reconcile_all_video_comment_stats() returns jsonb`**.
   - Loop over workspaces and call (1) for each.
   - Return the totals plus a `drifted` array of the per-workspace results where
     `rows_corrected > 0`. That array is what the cron run history will show.
   - Same revoke and grant as (1).
3. **Guard against moving a comment:** a `BEFORE UPDATE OF video_id, workspace_id ON
   public.comments` row trigger. It raises when either value actually changes (`is distinct
   from`), with errcode `23514` and a message that says comments do not move between videos.
   - If you find **any** existing code path that legitimately moves a comment, stop and report
     it in #66 instead of adding the guard.
4. **Schedule** (2) nightly with pg_cron as job `reconcile-video-comment-stats` at
   `'37 2 * * *'`.
   - Copy the pattern in `supabase/migrations/20260917110000_sentiment_tick_scheduled.sql`:
     skip with a notice where pg_cron is unavailable (PGlite), and unschedule by name first so
     the migration is safe to run twice.
   - Don't use :00. That minute is already busy.
5. Regenerate `supabase/schema/current.sql` with the repo's tooling. `npm run
   db:snapshot:check` must pass; that was WO-9's first red CI.

## Acceptance criteria
- [ ] **Corrects drift.** In a seeded workspace with comments on 3+ videos, corrupt the stats
  table directly: a wrong `total` on one video, a wrong `analysed` on another, and a deleted
  row for a third that has comments. After `reconcile_video_comment_stats(w)`:
  - every row equals a brute-force count;
  - `rows_corrected` = 3;
  - `videos_checked` = the number of videos in `w`.
- [ ] **Clean is a no-op.** On an exact table, `rows_corrected` = 0, and the stats rows are
  unchanged: same `xmin`, or an equivalent proof that nothing was rewritten.
- [ ] **Isolation.** Drift injected into workspaces A and B, then `reconcile(A)`, fixes A only.
  `reconcile_all` then fixes both, and lists both in `drifted`.
- [ ] **Privileges.** `anon` and `authenticated` cannot execute either function.
  `service_role` can.
- [ ] **Guard.**
  - `update public.comments set video_id = <another video in w>` raises `23514`, and so does
    the same for `workspace_id`.
  - `purge_comment_text()` and a re-run of the comment upsert path still succeed. The existing
    `supabase/tests/retention.test.ts` must stay green.
- [ ] **Schedule.** A test reads the migration file and asserts:
  - `cron.schedule('reconcile-video-comment-stats', '37 2 * * *', ...)`;
  - an unschedule by that name before it;
  - the pg_cron-availability guard.
- [ ] **Mutation proof:**
  - comparing only `total` (ignoring `analysed`) fails the drift test;
  - dropping the guard trigger fails the guard test;
  - writing corrected values with a direct `UPDATE`, instead of through
    `refresh_video_comment_stats`, fails a structural test you add. Assert from
    `pg_get_functiondef` that the reconcile calls the helper and does not `update
    private.video_comment_stats` itself.
- [ ] `npm run check`, `npm run test:db` and `npm run db:snapshot:check` pass. Paste the
  summary lines.
- [ ] No deploy, no remote migration, never push to `main`.

## Notes
- **Cost.** Reconcile reads every comment in a workspace once, which is the same shape as the
  WO-9 seed (29 s for all workspaces on production). That is fine nightly, and it never runs on
  a page view. Say in the PR if you see a reason it would not be.
- **When it finds drift.** Seeing a non-zero `rows_corrected` on production means a write path
  bypassed the triggers. The fix for that is a new WO, not a more frequent reconcile.
