## Why
Audience overlap (roadmap phase 3) counts **distinct commenters** across channels. Today several collectors record an unknown author as one shared value: `"tg_unknown"`, `""`, or the string `"None"`. Every unknown commenter then becomes **one person** who comments everywhere, and the overlap is inflated. Two collectors also fall back to a **handle**, which the user can change, so one person can become two. Both break invariant 3 in `docs/agents/CONTEXT.md` §5: unknown is `null`, never a stand-in value.

| `workers/python/src/collectors/tiktok_collector.py:329` | TikTok, fixture mode | the handle `user.unique_id` **before** the stable `author_id` |

The contract already allows null (`packages/contracts/src/jobs.ts:68` has `author_channel_id: z.string().nullable()`, and `collectors/protocol.py:19` has `str | None = None`). Only the collectors are wrong.

## Tasks
1. Add `collectors/identity.py` with `stable_author_id(value: object) -> str | None`. It returns `None` for `None`, `""`, whitespace-only strings, and the literal strings `"None"` and `"null"`. Otherwise it returns `str(value).strip()`. Ints stay digits: `123` becomes `"123"`, never `"123.0"`. Add a one-line docstring saying why: a shared placeholder merges strangers into one commenter.
2. Route every site in the table through it. For Telegram live, use `stable_author_id(f"tg_{msg.sender_id}") if msg.sender_id else None`. Keep the `tg_` prefix, because existing rows use it.
3. Remove the handle fallbacks. Bright Data X uses only `user_id`. The TikTok fixture uses `author_id` / `user.id` / `user.uid` only. The handle may still feed `author_name`, which is display text, not identity.
4. Update the two existing TikTok fixtures (`test_tiktok_collector.py:51,59` and `test_omnichannel_e2e.py:225,232`) so each item carries a stable `id`. Keep `unique_id` as display data.
