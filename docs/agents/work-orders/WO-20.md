## Why
Competitor discovery ranks channels by genre **and** size, activity and growth. The columns `channels.subscriber_count`, `total_view_count` and `video_count` exist (`20260924010000_interaction_metrics_and_storytelling.sql:22-26`), but **nothing writes them**: `git grep -n subscriber -- workers/python/src/collectors` is empty. There is no history either, so growth can't be computed. The channel's own text (description, keywords, topic categories) is the main input to genre classification, and we don't store it.

The data is free to get. Every discover already calls `channels.list` (`workers/python/src/collectors/youtube_api.py:357`, `part=contentDetails`, 1 unit). Asking for more parts in that same call costs nothing extra. WO-21 makes the worker send them. This work order gives them somewhere to land.

## Design (decided)
**Columns on `public.channels`** (all nullable; null means not observed):
`description text`, `keywords text[]`, `topic_categories text[]`, `country text`, `default_language text`, `channel_published_at timestamptz`, `subscriber_count_hidden boolean`, `profile_observed_at timestamptz`, `stats_observed_at timestamptz`.

**New table `public.channel_stats_daily`**: `(workspace_id uuid, channel_id uuid, day date, subscriber_count bigint null, view_count bigint null, video_count bigint null, observed_at timestamptz not null)`, with primary key `(workspace_id, channel_id, day)` and FK `(workspace_id, channel_id)` → `channels(workspace_id, id)`. RLS uses the tenant `tenant_read` pattern and has no write policies.

**`private.worker_commit_channel(token_hash text, j uuid, t uuid, profile jsonb) returns jsonb`** (`SECURITY INVOKER`, `search_path=''`), with `public.svc_worker_commit_channel` wrapping it and the same grants as the catalogue wrapper.
- `profile` must be an object. `external_channel_id` must equal the job channel's, or it raises `channel_profile_mismatch`.
- Numbers must be `number|null`, and arrays must be arrays of strings, or the whole payload is refused with `invalid_channel_profile` (22023, invariant 4).
- **A key that is absent means "not observed": leave the column as it is. A key present with `null` means "observed unknown": write null.** A hidden subscriber count arrives as `subscriber_count: null, subscriber_count_hidden: true`. It is never 0.
- It writes the current values on `channels` and stamps `profile_observed_at` / `stats_observed_at` (only for the groups present). It upserts today's row (UTC day) in `channel_stats_daily`. Committing twice in a day leaves one row with the latest values.

**Gateway:** `/worker/commit-channel` mirrors `/worker/commit-catalogue` (same credential, job and lease checks). The body is `{ job, lease, profile }`. Add a zod schema `ChannelProfileCommit` in `jobs.ts`.

**Retention:** `private.purge_channel_profile(retain_text interval default '30 days', retain_stats interval default '30 days')`.
- It nulls `description`, `keywords`, `topic_categories` where `profile_observed_at < now() - retain_text`.
- It deletes `channel_stats_daily` rows older than `retain_stats`.
- Schedule it daily next to `purge-comment-text` with the same pg_cron guard.

Under YouTube's policy the text is on a 30-day cycle. Stats may be kept up to 36 months **only after** the owner's Derived Metrics application is accepted (decision 2026-10-17). That change is an argument in the cron call, not new code. Say so in a SQL comment.

## Acceptance criteria
- [ ] Each new test fails on the old code (say how you proved it)
- [ ] Tenant isolation: a member of workspace B can't `select` workspace A's `channel_stats_daily` rows (direct request); a worker credential with another job's lease is refused
- [ ] Refused whole, with nothing written: non-object payload; string where a number belongs; non-string array item; YouTube `external_channel_id` of another channel
- [ ] Absent key leaves the old value; `null` writes null; hidden subscribers give `subscriber_count is null and subscriber_count_hidden`; never 0
- [ ] Two commits on the same day give one `channel_stats_daily` row with the second commit's values (idempotent)
- [ ] `purge_channel_profile('30 days','30 days')` nulls text observed 31 days ago, keeps text observed 29 days ago, and deletes stats rows older than 30 days
- [ ] Gateway handler test: `/worker/commit-channel` passes `{job, lease, profile}` through and rejects a body without `profile`
- [ ] `npm run db:snapshot:check`, `npm run test:db`, `npm run check` and `npm run test:e2e` pass (paste the summary lines)
