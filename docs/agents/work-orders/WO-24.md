## Why
B-4 scores competitors by how close their genre mix is to the customer's channel, so each channel
needs a profile: a weight per genre, not a single label. The roadmap defines the profile:
- **Main** is the highest-weighted level-1 genre.
- **Primary** is the highest-weighted level-2 genre under Main.
- **Secondary** are level-2 or level-3 genres outside Primary with weight ≥ 15%.

The workspace owner can correct the profile, and the correction wins, as in `comment_reviews`.

## Tasks
1. **The table.** Create `public.channel_genres`:
   - Columns: `workspace_id`, `channel_id`, `classification_key`, `taxonomy_version int`, `genre_key`, `level smallint`, `weight numeric(5,4)` (0..1), `videos int`, `computed_at`.
   - Unique `(workspace_id, channel_id, classification_key, genre_key)`. FK `(workspace_id, channel_id)` to `channels` with cascade delete. FK `(taxonomy_version, genre_key)` to `genre_taxonomy(version, key)`.
   - RLS: tenant read through `private.has_role(workspace_id)`. No writes for `authenticated` or `anon`.
2. **The computation.** `private.refresh_channel_genres(w uuid, c uuid, key text)`, `SECURITY DEFINER`, `search_path=''`:
   - **Input:** the channel's `succeeded` rows in `video_genre_predictions` under `key`, for its 50 most recent videos by `published_at` (WO-22's window).
   - **Video weight:** `ln(1 + coalesce(view_count, 0)) + 1`, times a recency factor `0.5 ^ (age_days / 90)` measured from `published_at`. A video with no `published_at` gets a factor of 0.5. A null view count is a weight of 1, not 0.
   - **Roll-up:** a video labeled at level 3 also counts toward its level-2 and level-1 ancestors, and a level-2 label counts toward its level-1 parent.
   - **Normalization:** weights are normalized per level, so each level's weights sum to 1 over the genres present.
   - **Write:** it replaces the channel's rows for `key` in one statement pair (delete, then insert).
   - **Minimum:** with fewer than **5** succeeded videos it writes nothing and deletes the old rows. Unknown is not zero (invariant 3).
   - **When it runs:** at the end of WO-22's `worker_commit_genres`, once per committed batch, for that batch's channel. A channel has at most 50 videos in the window, so this stays well under the 8 s ceiling. Measure it in a test with 50 predictions.
3. **Human correction.** Create `public.channel_genre_reviews`:
   - Columns: `id`, `workspace_id`, `channel_id`, `taxonomy_version`, `main_key`, `primary_key null`, `secondary_keys text[] not null default '{}'`, `reason text`, `reviewer_id`, `created_at`.
   - The latest row per channel wins.
   - `main_key` must be level 1. `primary_key` must be a level-2 child of `main_key`. Each secondary key must be level 2 or 3 and distinct. There are at most 5 secondary keys. All keys must exist in `taxonomy_version`.
   - Add `public.channel_genre_review_set(p_channel uuid, p_main text, p_primary text, p_secondary text[], p_reason text)`. Only `workspace_owner` and `analyst` may call it. It refuses with `invalid_input` and writes one `audit_events` row (`action 'channel_genre_review_set'`).
   - Add `public.channel_genre_review_clear(p_channel uuid)`, which inserts nothing and deletes the channel's reviews. It writes an audit row too.
4. **Read RPC.** `public.channel_genre_profile(p_channel uuid)` returns jsonb, for any member:
   - When `private.switch_on('genre_classification')` is false, it returns `{blocked: 'genre_classification_off'}` and nothing else. The UI must never show genres before acceptance (policy §3).
   - Otherwise it returns `{taxonomy_version, classification_key, source: 'reviewed'|'model'|null, main, primary, secondary: [...], weights: [{genre_key, level, weight, name_ar, name_en}], videos, computed_at}`.
   - `source` is `reviewed` when a review exists, and then main, primary and secondary come from it; the weights still come from the model.
   - With no rows it returns `source: null` and empty lists, never zeros.
   - Main, primary and secondary follow the roadmap rule above. Ties are broken by `genre_taxonomy.position`.
5. **Contract.** Add `ChannelGenreProfileSchema` (zod, `.strict()`) in `packages/contracts/src/genres.ts`, covering both the `blocked` shape and the profile shape.

## Acceptance criteria
- [ ] Each new test fails on the old code (say how you proved it)
- [ ] A channel with 4 succeeded videos has no profile. With 5 it has one, and its weights per level sum to 1 (± 0.0001).
- [ ] Roll-up: a level-3 label raises its level-2 and level-1 ancestors. A worked example is checked against hand-computed weights.
- [ ] The view and recency weighting changes the order in a constructed case. A null view count is weight 1, not 0.
- [ ] Main, Primary and Secondary follow the rule, including the 15% cut-off and the tie-break.
- [ ] Reviews:
  - a review overrides main, primary and secondary;
  - clearing it restores the model's;
  - each invalid combination is refused (wrong levels, a primary that is not a child of main, unknown keys, 6 secondaries);
  - a viewer and a non-member are refused;
  - one audit row is written per change.
- [ ] The switch off gives `blocked` from `channel_genre_profile`, even when rows exist.
- [ ] Tenant isolation: workspace A cannot read B's profile or reviews, and `authenticated` cannot write either table directly.
- [ ] The recompute after a 50-row commit is timed in the test and stays under 1 s on PGlite.
- [ ] `npm run check` passes (paste the summary lines). Skip `test:e2e`, `semgrep` and `gitleaks` locally, as the constraints say.
