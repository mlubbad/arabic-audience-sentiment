## Why
WO-23 stores competitor candidates (manual picks and featured channels) as bare YouTube channel ids, with an optional title and handle (`20261114010000_competitor_candidates.sql:77`). The scoring (WO-26) ranks candidates by content similarity, language and market, and size. None of that exists for a candidate today, so no candidate can be scored.

YouTube returns everything needed in **one `channels.list` call for up to 50 ids (1 quota unit)**: `snippet` (country, default language), `statistics` (subscribers, views, videos) and `topicDetails` (topic categories). This work order fetches that for each channel's candidates during the discover the channel already runs, and stores it on the candidate rows.

## Design (decided)
1. **Columns on `public.competitor_candidates`** (all nullable; null means not observed):
   - `subscriber_count bigint`, `subscriber_count_hidden boolean`, `view_count bigint`, `video_count bigint`;
   - `country text`, `default_language text`, `topic_categories text[]`;
   - `profile_observed_at timestamptz`.
2. **`private.worker_candidates_due(token_hash text, j uuid, t uuid) returns jsonb`.** Through `private.worker_job`, it returns up to **50** distinct `candidate_external_id`s of the job's channel (platform `youtube`), where `profile_observed_at` is null or older than **7 days**, oldest first. It is wrapped by `public.svc_worker_candidates_due`, with the same grants as `svc_worker_featured_due`.
3. **`private.worker_commit_candidate_profiles(token_hash text, j uuid, t uuid, profiles jsonb) returns jsonb`**, wrapped by `public.svc_worker_commit_candidate_profiles`.
   - `profiles` must be an array of at most 50 objects, each with `external_channel_id` among **this job channel's** candidates. Otherwise the whole call is refused with `invalid_candidate_profiles` (22023), and nothing is written (invariant 4).
   - Per key: **absent means not observed** (leave the column), **null means observed unknown** (write null). Types follow WO-20's validation: counts are non-negative integer numbers or null, and arrays hold strings.
   - It updates every candidate row of that workspace, channel and id (one per source), and sets `profile_observed_at = now()` when at least one key besides the id is present.
   - It returns `{"updated": n}`.
4. **Retention.** `private.purge_channel_profile` additionally nulls all eight columns on candidates whose `profile_observed_at` is older than `retain_text`, since these are YouTube API data on the 30-day cycle. Keep its existing behaviour exactly.
5. **Gateway and contract.** `/worker/candidates-due` and `/worker/commit-candidate-profiles`, beside `featured-due` and `commit-featured`, with the same lease checks and SQLSTATE mapping. The contract adds `CandidateProfilesCommit` (`.strict()`, array ≤ 50).
6. **Worker.**
   - `YouTubeAPI.channel_profiles(ids: list[str]) -> list[dict]`: one `channels.list` request with `part=snippet,statistics,topicDetails` and `id=<comma-joined ≤50>`. Each item is parsed with the existing `_channel_profile`. Drop `description`, `keywords` and `channel_published_at` from the result: candidates store only the fields in item 1.
   - In `_discover`, after the featured block, for YouTube:
     - `due = control.candidates_due(lease)`;
     - if it is non-empty, fetch and `control.commit_candidate_profiles(lease, profiles)`;
     - `LeaseLost` is re-raised; a `ControlPlaneError` or a `CollectionError` from the fetch finishes the discover **`partial`** with `candidate_profiles_failed` (invariant 2);
     - an id YouTube doesn't return (deleted channel) is committed as `{external_channel_id, subscriber_count: null, view_count: null, video_count: null}`, observed but unknown, so it isn't asked again for 7 days.

## Acceptance criteria
- [ ] Each new test fails on the old code. Show it by **mutating the guard**, not by deleting the migration.
- [ ] **Due list:** at most 50; only stale or never-observed candidates; only the job's channel; and another workspace's credential or lease is refused.
- [ ] **Commit is refused whole** (nothing written) for:
  - a non-array;
  - more than 50 items;
  - an id that is not this channel's candidate;
  - a string count;
  - a non-string array item.
- [ ] **Commit semantics:** absent leaves, null writes null; both source rows of one id are updated; `profile_observed_at` is set.
- [ ] **Purge:** candidate columns are nulled after 30 days unrefreshed and kept at 29. The existing channel-profile purge behaviour is unchanged (its tests still pass).
- [ ] **Worker:**
  - exactly **one** `channels.list` request for ≤ 50 ids, with exactly `part=snippet,statistics,topicDetails`;
  - a missing id is committed as unknown;
  - a failed fetch or commit gives `partial candidate_profiles_failed`;
  - no due ids means no request.
- [ ] **Seam:** `golden_candidates.json`, produced by the Python builder, is committed through PGlite's real `svc_worker_commit_candidate_profiles`.
- [ ] `npm run db:snapshot:check`, `npm run test:db`, `npm run worker:test`, `npm run worker:lint` and `npm run check` pass (paste the summary lines). E2e runs in CI, not in Codex's sandbox.
