## Why
WO-25 gives each competitor candidate its public profile: subscribers, views, videos, country, language and YouTube topic categories. This work order turns candidates into the product's competitor list:
- a **score with its reasons**;
- the customer's decision to **track** or **dismiss** a candidate, limited per plan;
- a **daily stats history** for tracked competitors, which the benchmark (WO-28) charts.

**Design decided by the PM (2026-10-20):** a tracked competitor is **not** registered as a channel. Channel limits are counted in many live functions, so adding competitor channels there would be a wide change. Tracking is a decision row plus a daily snapshot, fed by WO-25's enrichment.

## Design (decided)
1. **Plan limit.**
   - Add `public.plans.competitors_limit int` (null means unlimited, check ≥ 0). Seed: `free 0`, `creator 3`, `creator_plus 3`, `pilot 3`, `agency 10`, `media 25`, `enterprise 25`, `owner null`.
   - Redefine `private.plan_limit` adding `when 'competitors' then p.competitors_limit`, with everything else unchanged.
2. **Decisions:** `public.competitor_decisions(workspace_id uuid, channel_id uuid, platform text default 'youtube', candidate_external_id text, status text check in ('tracked','dismissed'), decided_by uuid references auth.users on delete set null, decided_at timestamptz not null default now())`.
   - Primary key `(workspace_id, channel_id, platform, candidate_external_id)`.
   - FK to `channels(workspace_id,id)` on delete cascade.
   - RLS `tenant_read`, no write policies; writes only through the RPC.
3. **History:** `public.competitor_stats_daily(workspace_id, channel_id, candidate_external_id text, day date, subscriber_count bigint, view_count bigint, video_count bigint, observed_at timestamptz not null)`.
   - Primary key `(workspace_id, channel_id, candidate_external_id, day)`.
   - FK to `channels` on delete cascade, and RLS `tenant_read`.
4. **Redefine `private.worker_candidates_due`:** a **tracked** candidate is stale after **1 day**, others after 7. Tracked candidates come first; the 50 cap is unchanged.
5. **Redefine `private.worker_commit_candidate_profiles`.** After the update, for each committed id that is **tracked** in this channel, upsert today's UTC `competitor_stats_daily` row from the candidate's current counts, the same way WO-20 builds `channel_stats_daily`. Counts write only when all three are present in the payload, so a partial set never stamps an old value as today's (the WO-20 review lesson).
6. **Redefine `private.purge_channel_profile`:** also delete `competitor_stats_daily` rows older than `retain_stats`.
7. **`public.competitor_decide(p_channel uuid, p_candidate_external_id text, p_decision text) returns jsonb`.**
   - `SECURITY DEFINER`, `search_path=''`. The caller must have role `workspace_owner` or `analyst` in the channel's workspace (`private.has_role(ws, array[...])`). The candidate must exist for that channel. Otherwise `forbidden` (42501) or `invalid_input` (22023).
   - `p_decision` is `tracked`, `dismissed` or `clear` (`clear` deletes the decision).
   - **Tracking** checks `private.plan_limit(ws, 'competitors')`. It counts the workspace's `tracked` decisions across all its channels, excluding this one if it's already tracked, and refuses `competitor_limit_reached` (P0001) when the count reaches the limit. Null means unlimited. A plan-less workspace gets `no_active_plan`, as `plan_limit` does.
   - It is idempotent and returns `{status, tracked_count, limit}`.
   - Revoke from `public, anon`; grant to `authenticated`.
8. **`public.competitor_suggestions(p_channel uuid) returns jsonb`.** Same access check as `competitor_candidates`. It returns `{channel: {...own profile...}, limit, tracked_count, candidates: [...]}`. There is one entry per `candidate_external_id`, merged across sources, **excluding dismissed**:
   `{external_id, title, handle, sources[], status: 'tracked'|null, subscriber_count, view_count, video_count, country, default_language, profile_observed_at, components: {content, locale, size}, score, tier, reasons: [...]}`.
   - **content** = the Jaccard of the own channel's and the candidate's `topic_categories`. Null if either is null or empty.
   - **locale** = the mean of the known comparisons among `default_language` equal and `country` equal (1 or 0 each). Null if neither pair is fully known.
   - **size** = `greatest(0, least(1, 1 - abs(log(cand_subs / own_subs)) / 2))` (base 10), only when both counts are known and above 0 and neither is hidden. Otherwise null.
   - **score** = the weighted mean over the **non-null** components, with weights content 0.5, locale 0.25, size 0.25. The weights of null components are redistributed. If **all three** are null, the score is null: "not enough data", never 0 (invariant 3). Round to 3 decimals.
   - **tier**, where ratio = cand_subs / own_subs:
     - `aspirational` when ratio ≥ 10 and content ≥ 0.3;
     - `direct` when 0.25 ≤ ratio ≤ 4 and content ≥ 0.5;
     - `indirect` when content ≥ 0.2;
     - otherwise `related`;
     - null when content or ratio is unknown.
   - **reasons**: machine-readable entries the UI renders in both languages, e.g. `{"kind":"shared_topics","value":3}`, `{"kind":"same_language"}`, `{"kind":"same_country"}`, `{"kind":"size_ratio","value":1.8}`.
   - **Order:** tracked first, then score descending with nulls last, then subscribers descending.
   - Genres (`channel_genres`) are **not** used in v1: candidates are not classified. Leave a SQL comment saying B-7 adds them.

## Acceptance criteria
- [ ] Each new test fails on the old code, shown by **mutating the guard** (not by deleting the migration).
- [ ] **Isolation:** a member of another workspace gets `forbidden` from both RPCs, and can't `select` the other workspace's `competitor_decisions` or `competitor_stats_daily` rows directly. A `viewer` can read suggestions but can't decide.
- [ ] **Limit:**
  - a `creator` workspace tracks 3, and the 4th gives `competitor_limit_reached`;
  - re-tracking an already-tracked candidate doesn't count twice;
  - `owner` is unlimited;
  - `free` gets the limit error on the first.
- [ ] **Score:**
  - hand-computed cases for full data;
  - one null component, with its weight redistributed;
  - all null, giving a null score (not 0);
  - a hidden subscriber count, giving a null size;
  - each tier boundary.
- [ ] Dismissed candidates are excluded; `clear` brings one back; one entry per id across two sources.
- [ ] **History:** a commit for a tracked candidate writes one row per day, and a second commit the same day updates it. An untracked candidate writes none. A commit missing one count writes none. The purge deletes rows older than `retain_stats`.
- [ ] **Due list:** tracked candidates go stale after 1 day and come first; untracked after 7.
- [ ] `npm run db:snapshot:check`, `npm run test:db` and `npm run check` pass (paste the summary lines). E2e runs in CI.
