## Why
A customer who tracks competitors wants one view comparing them with their own channel. The data exists:
- the own channel's daily public stats in `channel_stats_daily` (WO-20);
- tracked competitors' daily stats in `competitor_stats_daily` (WO-26).

Both are kept 30 days today, and up to 36 months once YouTube accepts the Derived Metrics application (owner, 2026-10-19). In this version we don't collect competitors' videos or comments, so there are no "top videos" and no "audience sentiment" for competitors (B-7/B-8 later). Show only what is measured.

## Design (decided)
1. **`public.competitor_benchmark(p_channel uuid, p_days int default 30) returns jsonb`.**
   - `SECURITY DEFINER`, `search_path=''`, with the same access check as `competitor_suggestions`. `p_days` must be between 7 and 1095, or `invalid_input`.
   - It returns `{days, series: [{kind: 'own'|'competitor', external_id, title, points: [{day, subscriber_count, view_count, video_count}], kpis: {...}}]}`.
   - The own channel comes first, then each **tracked** competitor in `competitor_suggestions` order.
   - **Points:** only the days that exist. **Never fill a missing day with 0 or a carried value** (invariant 3).
   - **kpis** per series, from the first and last points within the window:
     - `subscribers` and `views`: the latest known value;
     - `subscribers_change` and `views_change`: last minus first, null if there are fewer than 2 points or either end is null;
     - `videos_per_week`: `(last.video_count - first.video_count) / (days between / 7)`, null if under 7 days between points or either count is null; negative values (deleted videos) are kept as they are;
     - `views_per_video`: `last.view_count / last.video_count`, null if either is null or the video count is 0.
   - A channel with no points still appears, with empty points and null KPIs.
   - Revoke from `public, anon`; grant to `authenticated`.
2. **UI section "Benchmark"** on the competitors page, below the suggestions, shown only when at least one competitor is tracked:
   - **KPI table**: one row per series (own first, highlighted). The columns are subscribers, the change over the window, views, views per video and videos per week. Unknown values show "—" with a tooltip saying why ("less than a week of history"). On phone width it becomes stacked cards, like `dashboard/Compare.tsx`.
   - **Line chart**: subscribers over time, one line per series. A toggle switches to views. Gaps stay gaps (Chart.js `spanGaps: false`).
   - **Window selector**: 7, 30 or 90 days. Show a note when the selected window is longer than the history kept: "History is kept for 30 days" (`ar`: «نحتفظ بالسجل 30 يومًا»).
   - **Labels:** the counts are **"from YouTube"**; the derived columns (change, per week, per video) are **"our calculation"** (`ar`: «حسابنا»). This is policy: derived metrics are labelled.
   - The empty state, "Track a competitor to compare", appears when none is tracked.
3. **Keep the RPC's work bounded**: at most 26 series (own plus the media/enterprise limit of 25) and at most 1095 days. Use the `(workspace_id, channel_id, day)` primary keys; no table scans.

## Acceptance criteria
- [ ] Each new test fails on the old code, shown by mutating the guard.
- [ ] **Isolation:** another workspace's member gets `forbidden`; untracked and dismissed candidates don't appear; `p_days` outside 7–1095 gives `invalid_input`.
- [ ] **Unknown is never 0:**
  - a missing day is absent, not zero;
  - fewer than 2 points gives null changes;
  - a video count of 0 gives null views per video;
  - under 7 days gives null videos per week;
  - all of these render "—" in the UI.
- [ ] **KPI arithmetic:** hand-computed cases, including a negative video delta.
- [ ] **The chart** draws one line per series with gaps preserved. The derived columns carry the "our calculation" label, and the counts "from YouTube", in both languages.
- [ ] `npm run db:snapshot:check`, `npm run test:db` and `npm run check` pass (paste the summaries). Attach Arabic and English screenshots at desktop and phone width.
