## Why
Overlap needs one stable identity per commenter across a workspace's channels, without keeping a readable id. ADR-0003 decided:
- a keyed hash;
- built by a drain outside `commit_batch`;
- kept 30 days, exactly like comment text;
- off until YouTube accepts the use case.

**Policy gate:** the owner has not yet received YouTube's acceptance for overlap (follow-up request in `docs/youtube-api-application-2026-10.md` §5). Nothing in this WO may build an identity while the switch is off.

## Design (decided)
1. **Switch.** Insert `('audience_overlap', false)` into `private.platform_switches` (WO-22's table). The existing `public.admin_set_platform_switch` flips it; don't add another setter.
2. **Pepper.**
   - A Vault secret named `audience_pepper`, created **inside the database** by the migration:
     - only when `vault` exists and the secret is absent;
     - from `extensions.gen_random_bytes(32)`, hex-encoded;
     - otherwise a `raise notice`, as the pg_cron guard in `20260914100000` does.
   - The value never appears in a file, a log, a return value or an error.
   - `private.audience_pepper() returns bytea`:
     - reads `vault.decrypted_secrets`;
     - raises `pepper_missing` (P0001) if absent;
     - is revoked from everyone except `service_role`.
3. **Tables** (in `private`, RLS on, no grants to `anon`/`authenticated`):
   - `private.audience_member_videos(workspace_id uuid, video_id uuid, member_hash bytea, comment_count int not null, last_seen_at timestamptz not null, primary key (workspace_id, video_id, member_hash))`, with FKs to `videos(workspace_id, id)` on delete cascade.
   - `private.audience_members(workspace_id uuid, channel_id uuid, member_hash bytea, first_seen_at timestamptz not null, last_seen_at timestamptz not null, comment_count int not null, is_suspected_bot boolean not null default false, primary key (workspace_id, channel_id, member_hash))`, with FKs to `channels(workspace_id, id)` on delete cascade.
   - `private.audience_drain_state(singleton boolean primary key default true check (singleton), last_seen_at timestamptz, last_id uuid)`. This is the watermark.
4. **Hash.** `extensions.hmac(c.platform || ':' || c.author_channel_id, private.audience_pepper(), 'sha256')`, computed only inside `SECURITY DEFINER` functions in `private`.
5. **Drain.** `private.drain_audience_members(max_comments int default 20000, budget interval default '60 seconds') returns int`.
   - **Shape:** like `drain_video_comment_stats` (#173):
     - `pg_try_advisory_xact_lock` (another run in progress returns 0);
     - a time budget checked between videos;
     - a subtransaction per video, with `raise warning` on failure.
   - **Switch off → returns 0 immediately and touches nothing.**
   - **Finding work:** read the next comments after the watermark, ordered by `(last_seen_at, id)`, limited to `max_comments`, using the existing partial index `comments_retention (last_seen_at) WHERE content_purged_at IS NULL`. Collect their distinct `(workspace_id, video_id)`. **Do not add an index to `public.comments` and do not change `commit_batch` or any trigger on `comments`.**
   - **Per touched video, recompute that video's rows from scratch:** delete its `audience_member_videos`, then insert one row per hash from that video's comments where:
     - `content_purged_at is null`;
     - `author_channel_id is not null` (unknown is not a person);
     - `author_channel_id <> channels.external_channel_id` of the video's channel (the owner is excluded).

     `comment_count = count(*)` and `last_seen_at = max(last_seen_at)`. Recomputing (not incrementing) makes a re-seen comment harmless.
   - **Then refresh `audience_members`** for that video's channel, for the hashes the video touched. Rows are re-aggregated from `audience_member_videos` joined to `videos` of that channel: `first_seen_at` = min, `last_seen_at` = max, `comment_count` = sum. Delete a member row whose aggregate is now empty.
   - **The watermark** advances to the last `(last_seen_at, id)` whose video was fully processed. A failed video does not advance past its comments.
   - Returns the number of videos recomputed.
6. **Retention.** A new definition of `private.purge_comment_text(retain interval default '30 days')`:
   - same signature, same return value (comments purged), same grants;
   - **also** deletes `audience_member_videos` and `audience_members` rows with `last_seen_at < now() - retain`, in the same transaction;
   - copy the current body exactly from `20260913235500_comment_text_retention.sql`, then add the two deletes.
7. **Rotation.** `public.admin_rotate_audience_pepper()`:
   - platform admin only (`public.is_platform_admin()`), otherwise `forbidden`;
   - replaces the Vault secret with a new random value via `vault.update_secret`;
   - truncates both member tables and resets the watermark to null;
   - writes `audit_events` with action `audience_pepper_rotated`;
   - never returns or logs the value.
8. **Cron**, guarded by the same "pg_cron unavailable" check: `audience-members-drain`, `*/10 * * * *`, command `set local statement_timeout = '5min'; select private.drain_audience_members()`.

## Acceptance criteria (each test fails on the old code or on a named guard mutation; say which line you changed)
- [ ] **Switch off:** the drain returns 0 and both tables stay empty, even with comments present.
- [ ] **Switch on:** two channels in workspace A share one commenter → one `audience_members` row per channel with the **same** `member_hash`; `audience_member_videos` has one row per (video, hash) with the right counts.
- [ ] The hash is never the raw id: `member_hash <> convert_to(author_channel_id, 'utf8')`, and it is 32 bytes. Changing the pepper changes it.
- [ ] **Excluded:** a null `author_channel_id`; a purged comment; the channel's own `external_channel_id`.
- [ ] **Re-seen comment:** running the drain twice, or after bumping `last_seen_at`, does not double `comment_count`.
- [ ] **Isolation:** the same commenter in workspaces A and B gives two separate rows (different `workspace_id`), and no function or table is readable as `authenticated` or `anon` (permission denied).
- [ ] **Retention:** a member row last seen 31 days ago is deleted by `purge_comment_text()`, and one seen 29 days ago stays. The comment purge itself still behaves as before.
- [ ] **Rotation:**
  - a non-admin gets `forbidden`;
  - an admin call empties both tables, resets the watermark and writes one audit row;
  - the next drain rebuilds with new hashes.
- [ ] **Budget and lock:** a run holding the advisory lock makes a second run return 0. `max_comments` bounds the work; the watermark resumes on the next run.
- [ ] **`pepper_missing`:** with the secret deleted, the drain (switch on) raises or warns without writing rows; the message does not contain any secret.
- [ ] `npm run db:snapshot:check`, `npm run test:db` and `npm run check` pass (paste the summaries). No e2e.
