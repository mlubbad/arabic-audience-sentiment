## Why
For a channel B that shares audience with channel A, show which of B's videos A's shared commenters engage with most: the "bridge videos". Rank them by count, and by affinity, so a huge video doesn't win only by size.

## Design (decided)
1. **`public.audience_shared_videos(p_channel uuid, p_other uuid, p_limit int default 10) returns jsonb`.**
   - `SECURITY DEFINER`, `search_path=''`. Revoke from public and anon; grant to authenticated.
   - **Gates, in WO-30's order:** `forbidden`, `feature_unavailable`, `plan_feature_unavailable`. Then:
     - `p_other` must be another channel of the **same workspace and platform**, else `invalid_input`;
     - `p_limit` must be 1–50, else `invalid_input`.
   - **The pair must be above WO-30's thresholds** (|A| ≥ 100, shared ≥ 10, from `audience_overlap_cells` and `audience_sizes`). Otherwise return `{status: 'below_threshold', videos: []}`.
2. **Per video of B**, from `audience_member_videos` restricted to the hashes that are members of A (non-bot):
   - `shared_commenters` = distinct shared hashes on that video;
   - `video_audience` = distinct non-bot hashes on that video;
   - `affinity = round(100 * (shared_commenters / video_audience) / (shared / |B|))`.
   - **Only videos with `shared_commenters ≥ 5` are returned.** That is a privacy floor: a list must never point at one or two people.
   - Return:

     ```
     {status: 'ready', videos: [{video_id, external_video_id, title, published_at,
                                 shared_commenters, video_audience, affinity}]}
     ```

     ordered by `shared_commenters DESC, affinity DESC, video_id`, limited to `p_limit`.
3. **No hash, no commenter id and no comment text** in the output.

## Acceptance criteria (each test fails on a named guard mutation; say which line)
- [ ] The gates work as in WO-30, plus:
  - a `p_other` from another workspace or platform gives `invalid_input`;
  - `p_limit` 0 and 51 give `invalid_input`.
- [ ] A pair below threshold returns `below_threshold` with no videos.
- [ ] **Counts:**
  - a video where 6 shared and 4 non-shared commenters appear → shared 6, audience 10;
  - a video with 4 shared commenters is not returned;
  - bots are excluded from both counts.
- [ ] **Affinity:** a hand-computed case. Two videos with equal counts are ordered by affinity.
- [ ] Only B's videos appear, never A's.
- [ ] `npm run db:snapshot:check`, `npm run test:db` and `npm run check` pass. No e2e.
