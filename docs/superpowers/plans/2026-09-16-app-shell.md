# App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the app shell's two hand-rolled interactive controls — the signed-in session control and the multi-workspace switch — onto the `ui/` component layer, and give the mobile menu the keyboard focus behaviour it lacks.

**Architecture:** `SessionControl` is extracted from `main.tsx` (a side-effecting entry point nothing can import in a test) into its own file and rebuilt on `ui/DropdownMenu`; `WorkspaceSwitch`'s native `<select>` becomes `ui/Select` with its rail-plane styling re-targeted in `app.css`; `AppLayout`'s mobile menu gains focus-in on open and `Escape` to close. Every trigger that sits on the dark rail keeps the rail's own ink — only the portaled menu/listbox wears `ui/`'s light panel styling. Two existing static-markup tests that assert `<option>` elements move to a jsdom test file, because Radix `Select` renders neither an `<option>` nor a resolved `SelectValue` under `renderToStaticMarkup`.

**Tech Stack:** React 19, TypeScript, React Router 7, `ui/DropdownMenu` + `ui/Select` (Radix, built in the previous phase), Vitest + jsdom + Testing Library (infrastructure from the previous phase), Playwright.

**Spec:** [docs/superpowers/specs/2026-09-16-app-shell-design.md](../specs/2026-09-16-app-shell-design.md)

## Global Constraints

- The rail's structure and its CSS classes (`.app-rail`, `.app-nav`, `.app-rail-foot`, …), `DESTINATIONS`, `NavIcon`, the announcement bar, `LanguageSwitch`, `CollectionState` and the plan card are untouched.
- Every trigger on the dark rail plane keeps rail ink (`--ink-on-dark` / the rail's translucent-white rules in `app.css`), never a light `ui-btn`/`ui-select-trigger` box. A focus ring on the rail uses `--focus-halo` (the light halo `brand.css` defines for dark planes), because `ui.css`'s default `--focus-ring` is near-black and invisible there.
- No new user-facing string is added: the account menu item reuses the existing `S.yourAccount` («حسابك»); `S.changeWorkspace` and `S.choosePlaceholder` move from the native `<select>` to the `Select` trigger/placeholder unchanged.
- No `letter-spacing` anywhere. Any numeral gets `.ui-num`.
- `RailState.test.ts`'s existing `CollectionState` cases, its "only one switch" source scan, and its signed-out cases are not modified; only its two `<option>`-asserting workspace cases move.
- `npm run check` must stay green; run the relevant subset after every task, the full chain before the final commit.
- Node is pinned to `22.14.0` (`engine-strict=true`); `.npmrc` saves exact versions.
- This checkout has another, concurrently-active session committing unrelated work throughout: stage by exact pathspec, never `git add -A`/`.`/`-a`; check `git status` before every commit; run `git show --stat <sha>` after every commit and confirm it holds exactly the intended files.

```tsx
/**
 * Whether you are signed in, and the one control that changes it.
 *
 * This belongs in the chrome, not on a page. Signing out lived in the body of
 * the account page, which meant leaving required first navigating to a
 * settings screen — and signing in was reachable only by guessing that the
 * item called "الحساب ومساحات العمل" was also the front door. Session state is
 * true of every route, so it is shown on every route.
 *
 * It takes the slot a decorative line was using ("فهم أوضح لكل تعليق"), which
 * is the trade this header needed: the tagline is on the landing page, where
 * someone is still deciding, and by the time a reader is inside the product
 * they have decided.
 *
 * Its own file, apart from main.tsx: that module calls createRoot().render()
 * at load, so nothing can import it in a test — the same reason the rail's
 * state lives in RailState.tsx.
 */
import { useState } from "react";
import { Link } from "react-router";
import { useSession } from "./session";
import { supabase } from "./supabase";
import { useStrings } from "./strings";

export function SessionControl() {
  const { session, loading } = useSession();
  const S = useStrings();
  const [busy, setBusy] = useState(false);
  const [failed, setFailed] = useState(false);
  // Nothing at all until it is known. A "sign in" that flips to "sign out" a
  // moment later reads as the page changing its mind about who you are.
  if (loading) return null;
  if (!session)
    return (
      <Link className="app-session app-session-in" to="/account">
        {S.signIn}
      </Link>
    );
  return (
    <div className="app-session">
      <span className="app-session-who" title={session.user.email ?? undefined}>
        {session.user.email ?? S.yourAccount}
      </span>
      <button
        type="button"
        disabled={busy}
        onClick={() => {
          if (!supabase) return;
          setBusy(true);
          setFailed(false);
          void supabase.auth.signOut().then(({ error }) => {
            setBusy(false);
            // Said, not swallowed: a sign-out that quietly failed leaves the
            // reader believing they have left a shared screen.
            if (error) setFailed(true);
          });
        }}
      >
        {busy ? S.signingOut : S.signOut}
      </button>
      {failed && (
        <span role="alert" className="app-session-error">
          {S.signOutFailed}
        </span>
      )}
    </div>
  );
}
```

## Task 3: `WorkspaceSwitch` on `ui/Select`, with its tests moved to jsdom

**Files:**
- Modify: `apps/web/src/RailState.tsx:35-78` (the `WorkspaceSwitch` function)
- Modify: `apps/web/src/app.css:1519-1529` (the `.app-shell .app-rail-workspace select` rule)
- Modify: `apps/web/src/RailState.test.ts` (remove the two `<option>` cases; keep everything else)
- Create: `apps/web/src/RailState.test.tsx`

**Interfaces:**
- Consumes: `Select`, `SelectTrigger`, `SelectValue`, `SelectContent`, `SelectItem` from `./ui/Select` (previous phase). `Select` takes `value`/`onValueChange`; `SelectValue` takes `placeholder`. Radix `Select` 2.3.7 (the pinned version) treats `value=""` on the root as "no selection, show the placeholder" — that is how the "choose" state is represented, in place of the native `<option value="">`. A `SelectItem` may **not** have an empty-string `value` (Radix throws), so no placeholder item is rendered.
- Consumes: `selectionFor(userId: string | null): string | null` and `resetWorkspaceSelection()` / `selectWorkspace(userId, id)` from `./workspaceSelection` — the store the switch reads and writes.

Why the tests move: `RailState.test.ts` renders with `renderToStaticMarkup` and asserts `<option … selected="">`. Radix `Select` renders no `<option>` — the listbox is portaled and mounted only while open — and `SelectValue` resolves the chosen item's text from items that register on mount, which never happens under static server rendering, so a static render shows an empty trigger. The two cases that assert the chosen name and the placeholder therefore move to a jsdom file; the single-workspace, signed-out and `CollectionState` cases are unaffected and stay.
