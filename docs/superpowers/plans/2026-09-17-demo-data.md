# Demo Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every «اصطناعي» placeholder with realistic, multi-dialect demo data: a generated demo fixture for visitors, a re-skinned e2e fixture with the same arithmetic, realistic catalogue titles, a rewritten landing demo, and honest wording.

**Architecture:** One authored content module (`apps/web/scripts/demo-content.mjs`) + one generator (`make-demo-fixture.mjs`) write both fixtures; `data.ts` picks the fixture path from `VITE_FIXTURE_DASHBOARD`; Playwright points at the e2e fixture; a unit test pins the committed JSON to the generator's output.

**Tech Stack:** Node ESM script (`node:crypto` sha256), Vitest, Playwright, the existing `@sentiment/contracts` schemas.

**Spec:** `docs/superpowers/specs/2026-09-17-demo-data-design.md`

## Global Constraints

- The e2e fixture keeps the current file's structure EXACTLY: same `id`s, `video_id`s, `author_channel_id`s, `likes_raw/likes_value`, `published_at`/`published_time_raw`/`timestamp_precision`, `is_reply`/`parent_comment_id`/`parent_source`, `by_channel_owner`, `comment_type`, `prediction`/`topic_prediction`/`reviews` blocks — only `author_name`, `text_raw`, `video_title`, the channel name, `field_provenance.origin`, and `content_hash` (recomputed; stale row keeps the old prediction hash) change.
- Arithmetic the 76 dashboard e2e tests assert must not move: they run against the e2e fixture. Only quoted human strings in tests change.
- «اصطناعي» must not appear in `apps/web/src/**`, `apps/web/public/fixtures/**`, `tests/e2e/**` after Task 4 (legal/*.ts excepted). A unit test enforces it.
- Content: dialect-consistent, linguistically correct, no real people, no politics/hate; sentiment/topic labels defensible. Use the content in Task 1 VERBATIM — do not paraphrase it.
- Another session edits this checkout: `docs/verification.md`, `.screenshots/` — never touch/stage/stash; stage by exact path; never `git add -A`; never `npm run format`; NEVER push (the controller pushes).
- Docs append-only; commit messages are sentences ending `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
